## Encrypted restart slice (host lifecycle still pending)

`optn-runtime::wallet_checkpoint::WalletCheckpoint` captures HD scope, raw
observations/provenance and local coin annotations in an actor turn. It reuses
core wallet-pack AES-GCM and the zeroizing `PackKey`. Decoding reconstructs HD
addresses from the actual origin and xPub, reprojects outputs from raw txs,
and restores labels/holds/Fusion depth only onto those outputs. It does not
restore login authority, spend approvals or freshness. Runtime restore requires
an already opened matching wallet/account/network with no active sync or current
snapshot. Restored coins are stale; the runtime blocks spend preparation and
spend/background authorization until successful refresh. Policy changes and
refresh initiation also clear old prepared spend plans. Dropped/timed-out caller
futures close a lease-owned oneshot channel that the driver observes directly;
cleanup cannot be lost when the action queue is full. The cancellation regression
retains prior coins and verifies a later HD refresh still succeeds.

`optn-chain-native::wallet_checkpoint::WalletCheckpointFile` writes encrypted
bounded files with fresh OS nonces, reusing the existing native atomic writer
and sidecar lock. Ciphertext revisions prevent accidental lost updates between
processes; wrong-key, foreign-wallet and corrupt-file writes are refused. This
is **not protection against malicious rollback of the disk**. Stored evidence
is not a trusted SHV/MMR initialization anchor.

The populated runtime restart test verifies retained HD scope, token custody,
labels/holds, wrong-key/tamper refusal, account/network/locked/late-load refusal,
stale spend gating and successful refresh after restart. Core tests (313),
runtime tests (81), native-stack tests (5), transport tests (9), strict runtime
and native Clippy, the WASM Tauri-transport UI check and architecture gate pass.
The bounded decoder mutation check rejects a change to every ciphertext/nonce
byte and authenticated malformed format, branch lengths and missing bookkeeping.
This is deterministic mutation coverage, not a coverage-guided fuzz run. All 100
ordinary CLI tests pass, including real native encrypted-file load/store, new
nonce/revision, stale-writer, wrong-key, foreign-wallet and corrupt-file refusal.
Strict CLI Clippy passes. Do not infer a mounted wallet lifecycle from component
tests. Core `CoinSet` insertion/replacement also rejects aggregate value overflow
atomically; the boundary test preserves the previous set. This is arithmetic
safety, not consensus/monetary-range validation.

Review follow-up: `ChainRevocation` is an irreversible source-stack lifetime
handle held outside the service mutex. Retired handles cannot start new routed
I/O; active calls cancel; publication checks the lease's source lifetime even
when a result was already prepared/queued. Broadcast cancellation stays

regressions pass in the runtime suite. Native host policy/credential changes must
revoke the stack and invalidate the actor before waiting for old service locks;
that integration now passes nine native host regressions. Old service handles
are revoked before lock waits, pending builds are generation-bound even when
the selection is unchanged, credential snapshots carry a revision, and final
publication checks both under the stack write lock. Closed owners stop rebuilds.
