## Encrypted restart slice (host lifecycle still pending)

`optn-runtime::wallet_checkpoint::WalletCheckpoint` captures HD scope, raw
observations/provenance and local coin annotations in an actor turn. It reuses
core wallet-pack AES-GCM and the zeroizing `PackKey`. Decoding reconstructs HD
addresses from the actual origin and xPub, reprojects outputs from raw txs,
and restores labels/holds/Fusion depth only onto those outputs. It does not
restore login authority, spend approvals or freshness. Runtime restore requires
an already opened matching wallet/account/network with no active sync or current
snapshot. Restored coins are stale; the runtime blocks spend preparation and
spend/background authorization until successful refresh. Policy changes and
refresh initiation also clear old prepared spend plans. Dropped/timed-out caller
futures close a lease-owned oneshot channel that the driver observes directly;
cleanup cannot be lost when the action queue is full. The cancellation regression
retains prior coins and verifies a later HD refresh still succeeds.

`optn-chain-native::wallet_checkpoint::WalletCheckpointFile` writes encrypted
bounded files with fresh OS nonces, reusing the existing native atomic writer
and sidecar lock. Ciphertext revisions prevent accidental lost updates between
processes; wrong-key, foreign-wallet and corrupt-file writes are refused. This
is **not protection against malicious rollback of the disk**. Stored evidence
is not a trusted SHV/MMR initialization anchor.

The populated runtime restart test verifies retained HD scope, token custody,
labels/holds, wrong-key/tamper refusal, account/network/locked/late-load refusal,
stale spend gating and successful refresh after restart. Core tests (313),
runtime tests (81), native-stack tests (5), transport tests (9), strict runtime
and native Clippy, the WASM Tauri-transport UI check and architecture gate pass.
The bounded decoder mutation check rejects a change to every ciphertext/nonce
byte and authenticated malformed format, branch lengths and missing bookkeeping.
This is deterministic mutation coverage, not a coverage-guided fuzz run. All 100
ordinary CLI tests pass, including real native encrypted-file load/store, new
nonce/revision, stale-writer, wrong-key, foreign-wallet and corrupt-file refusal.
Strict CLI Clippy passes. Do not infer a mounted wallet lifecycle from component
tests. Core `CoinSet` insertion/replacement also rejects aggregate value overflow
atomically; the boundary test preserves the previous set. This is arithmetic

## Shared send caller audit and funding validation

The continuation verified PR63 head `f6eb8301` and a clean tracked worktree before
editing. That head's Rust coverage, dependency policy, feature/fuzz compilation,
Semgrep, JavaScript/TypeScript CodeQL and supply-chain jobs passed; Rust nextest
and Rust CodeQL were still running at the observation. Do not infer alert closure
from an Actions job succeeding.

The actual remaining Send gap is concrete: `optn-ui/src/tools.rs` dispatches
`PrepareSend` then `AuthorizeSpend`; `optn-app` produces an intent and
`SpendAuthorized`, but no runtime handler turns that event into transaction bytes.
`optn-core/src/spend.rs::sign_seed_spend` only derives a public key and returns
`SignedSpend`; despite its name it does not sign a transaction. Do not use it as
signing evidence. The independent CLI wallet console currently admits security
navigation and sync/history, not `PrepareSend`. Legacy CLI `Send` instead uses
`spend_to` and the real `tx::Transaction::sign`. Its managed-wallet path is still
blocked by the shared stale-state guard after reopen; bypassing that guard or
calling the legacy scanner from the GUI would violate the intended architecture.

Tracing all four production callers of `tx::select_coins` (ordinary/RPA/token
funding in the CLI) exposed unchecked fee multiplication and duplicate outpoint
accounting. This commit rejects overflow in size, fee, target-plus-fee and funding
totals, and rejects repeated funding outpoints before selection. For example,
226 bytes at a fee rate of 2^63 previously panicked in debug and wraps to zero
with unchecked arithmetic. The regression reproduced the debug panic before the
fix, then passed in debug and optimized release builds. Distinct output indexes
of the same transaction remain selectable. All 16 transaction tests, core strict
Clippy, independent CLI all-target compilation and the architecture gate pass.
`estimate_size` now returns a checked `Result`; all repository callers compile.
No dependencies, scanner changes, alert dismissals or live transactions were added.

The next connected milestone must use the existing real transaction engine inside
the shared runtime: bind preparation to fresh HD observations and the selected
account, persist change allocation and pending-spend state, require approval of
the actual outputs/fee, sign without exposing keys through the renderer, and send
through the selected policy route while retaining uncertain broadcasts. Then wire
both interfaces and verify restart/retry on Chipnet. The changes above harden its
existing funding primitive; they do not claim that this milestone is complete.
