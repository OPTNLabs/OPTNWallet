## The thing that will bite you first

**`--workspace` and `--all` cover 9 of the 14 crates.**

The root `Cargo.toml` excludes `crates/optn-core`, `crates/optn-cli`,
`crates/optn-ui-egui` and `src-tauri`; `fuzz` declares its own workspace. So:

- `cargo build --workspace` does not compile `src-tauri`. A syntax error there
  reached CI in this session and broke every Preview, Desktop E2E and CLI job
  while the local run reported "20 suites green".
- `cargo fmt --all` does not format `optn-cli`. One unwrapped `assert!` turned
  all seven CLI targets red.
- `cargo deny --manifest-path Cargo.toml` does not see `src-tauri`. CI checks
  three manifests; only the root was verified locally, and the other two failed.
- There are **six** lock files. `optn-core` is a *path* dependency of
  `optn-cli`, `src-tauri` and `fuzz`, so one dependency added to it invalidates
  four. CI's lockfile job only checks three of the six; the rest fail later, in
  the build jobs, where the cause is much less obvious.

Before pushing any Rust change:

```sh
for d in crates/optn-core crates/optn-cli crates/optn-ui-egui src-tauri fuzz; do
  (cd "$d" && cargo check --all-targets && cargo fmt --all -- --check) \
    || echo "FAILED: $d"
done
for d in . crates/optn-core crates/optn-cli crates/optn-ui-egui src-tauri fuzz; do
  (cd "$d" && cargo metadata --locked >/dev/null) || echo "STALE LOCK: $d"
done
```

Then the ordinary ladder: `cargo fmt --all -- --check`, `cargo clippy
--workspace --all-targets --all-features -- -D warnings`, `cargo test
--workspace`, `cargo run -p xtask` (architecture), `cargo run -p xtask --
parity`, `cargo check -p optn-ui --target wasm32-unknown-unknown`, and
`npx tsc --noEmit` plus `npx vitest run`.

The wasm target matters: `optn-ui`'s components are `#[cfg(target_arch =
"wasm32")]`, so a native test run never compiles them. A missing match arm got
through that way.

Two more traps worth knowing rather than rediscovering:

- **`yarn.lock` churns whenever npm runs here.** It swaps Linux esbuild binaries
  for Windows ones and drops ~1350 lines. It is tracked but nothing regenerates
  it deliberately. Check `git status -- yarn.lock` before every commit; it has
  slipped in three times.
- **Lock files race the crates.io index.** `cargo generate-lockfile` locally and
  on the runner minutes apart can differ by a patch release, and the check
  diffs them. When it happens, take CI's own regenerated file — it is uploaded
  as the `generated-lockfiles` artifact.

## What is done

Layering, and it is guarded rather than described. `xtask architecture` fails
the build if a UI framework reaches `optn-app`/`optn-transport`, if an Apple
package name appears in wallet-authority crates, or if the two renderers' host
blocks differ by more than the one `type Ui<T>` line. `xtask parity` guards the
product decisions — Watch Only on every surface, hardware where an integration
exists, evidence that actually points at something.

**Read `docs/architecture-guards.md` before you touch either.** It says what
each check defends and what a failure means, because the tempting fix — an
allow-list entry, a deleted assertion, a widened match — turns a decision into a
comment nobody reads. Two of these checks were *tightened* when they produced
false positives rather than relaxed; that is the pattern to copy.

- **`optn-core`** (16k lines) — no I/O, no RNG, wasm-safe, Kani-verified, and
  deliberately **dependency-free in dev-dependencies**. Wallet truth: HD, PSBT,
  CashAddr, multisig, BSMS, NIP-44, RPA, Fusion, conformance harness.
- **`optn-app`** — view models, `AppState`/`AppAction`, surface capabilities.
- **`optn-transport`** + `optn-transport-tauri` — the `AppTransport` seam.
- **`optn-ui`** (Leptos/wasm), **`optn-ui-text`**, **`optn-ui-egui`** — three
  renderers. The swap is one line and `xtask` proves it.
- **`optn-platform`** → **`optn-platform-native`** / **`optn-platform-apple`**.
  All Apple code lives in the Apple crate; `optn-platform` is
  provider-agnostic.

Interop, all anchored against something outside this repository:

| Claim | Anchored against |
| --- | --- |
| Redeem script and address | Electron Cash 4.4.5, and `optn-multisig-core` compared directly |
| Descriptor form | Paytaca's source — `sortedmulti`, BIP-389 `<0;1>/*` |
| BSMS round 1 + signatures | BIP-129's published vectors, both signature encodings |
| BSMS encryption | BIP-129's vector, every value reproduced byte for byte |
| NIP-44 | reference implementation, byte-identical vectors |
| PBKDF2 | Python `hashlib` at 1, 1000 and 600,000 rounds |

**Every real bug this session came from checking against something outside the
repo.** The local tests were green throughout. A test that signs a record and
then verifies it proves the digest is built *consistently*, not correctly.

## What is left

### Needs a physical device

- **Trezor in the browser.** `@trezor/connect-web` was removed — it was the sole
  source of five high-severity CVEs, pulling the whole Stellar SDK in. The
  replacement is `@trezor/transport` (Trezor's own, ships a WebUSB backend, no
  Connect chain SDKs). `TrezorService.ts`'s browser paths throw
  `browserNotWired()` naming what is missing rather than pretending.
- **Ledger signing.** Connection and account export are migrated to the Device
  Management Kit; the multi-round transaction APDUs are not. `ledgerBchApdu.ts`
  is pure byte functions and fully tested; `LedgerDmkSession.ts` holds the
  session.
- **Trezor and OneKey desktop `SignTx`** — pre-existing, both throw
  "SignTx multi-round is next".

### Needs a decision

- **CodeQL: 39 alerts, all verified false positives.** 37 sit inside
  `#[cfg(test)]`; the rest are the NIP-44 salt (spec-mandated by
  `salt=utf8_encode('nip44-v2')`) and a PBKDF2 *output* buffer. Evidence is in
  the PR comments. Fixing the source would be wrong — contorting crypto to
  satisfy a scanner is the bad kind of change. This needs dismissal, which is
  the repository owner's call and was deliberately not done unilaterally.
- **Ledger's Bitcoin Cash path.** `@ledgerhq/hw-app-btc` is deprecated as of
  September 2026 per Ledger's own portal. Its official replacement,
  `device-signer-kit-bitcoin`, has **no** BCH support — checked by unpacking the
  package: no `cashaddr`, no `forkid`, no `additionals`, and its builder takes
  no currency option. Twelve signer kits exist and none is BCH. The path
  forward is DMK's transport plus our own app-binder, which is what
  `ledgerBchApdu.ts` starts.
- **Cosigner cap: 15 or 16?** `optn_core::multisig::MAX_COSIGNERS` is 16, which
  is what `OP_16` encodes. `optn-multisig-core` (from #65) caps at 15, which is
  Electron Cash's limit. A test in `crates/optn-cli/tests/` pins the
  disagreement. One of them should move.

### Known gaps, stated rather than hidden

- **Nothing has been exchanged with a running Paytaca.** Everything is checked
  against their source and against BIP-129, never against a file their app
  produced.
- **Paytaca does not verify BSMS records on import.** Their round-2
  first-address check is written and commented out
  (`wallet.js`, `static parseBsmsDescriptor`), and round-1 signature
  verification is absent from `src/lib/multisig/` entirely. Their AES-256-GCM
  choice is *not* an interop problem — that is their coordination-server
  transport, not the multisig core, and they said so correctly.
- **Hardware is off on Android and iOS** — no native plugin yet. It is on for
  desktop, web and extension, where a Ledger (WebHID), a OneKey (its own web
  SDK) and a Keystone (camera) all work.
- **Tangem needs native code.** NFC only, so phones only, and both of its
  JavaScript bridges are archived — the supported route is their Swift and
  Kotlin SDKs.

### Reading the parity matrix

`cargo run -p xtask -- parity` prints mostly `fail`. That is the
**production-ready** grading: it counts only `e2e` or `device` evidence, so
anything with `unit` evidence reads as fail. It does not mean the feature is
missing. `parity matrix integrity: PASS` on the same run is the check that
actually gates.

## Conventions that are not obvious

- **Push to `fork`, not `origin`**, and use an explicit refspec:
  `git push fork HEAD:agent/rpa-shared-vectors`. The worktree's local branch is
  named `pr63-head`, which is *not* the PR's head ref — pushing the bare name
  silently creates a junk branch. (One such stray `pr63-head` exists on the fork
  and should be deleted.)
- **Merge, never rebase.** The branch is shared — Codex pushes to it — and a
  rebase needs a force-push that would discard their work. It is also 497
  commits, so a rebase replays every conflict once per commit.
- **Patch, never regenerate.** Codex edits this worktree live. Whole-file writes
  destroy in-flight work. `src-tauri/src/fusion/` and `nostr/` are theirs;
  coordinate before touching them. Running `cargo fmt` inside `src-tauri` will
  reformat four of their files — revert those, the state is pre-existing.
- **No Claude attribution** in OPTN commits or PR bodies.
- **Squash-merge** is the repository's convention: every recent commit on `dev`
  is a single commit ending in `(#NN)`.
- `.github/workflows/` is off-limits for edits in this lane.
- Chipnet only in tests, never mainnet. No seeds, keys or mnemonics logged.
